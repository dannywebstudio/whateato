## 구현한 개선 기능
1. `db/migrations/008_restaurant_quality_review.sql`: 원장과 별도의 품질 검토 테이블, `pending`/human `confirmed_hold`/`dismissed` 상태, 출처/검토자/검토 시각. 심각한 사유와 근거 및 검토자가 있어야만 확정 보류 등록 가능. 한 번 보류한 대상을 복원하려면 결정 상태를 별도 검토.
2. `db/migrations/009_quality_candidates_non_destructive.sql`: 좌표 누락, 도로명/지번 주소 양쪽 누락, 완전히 같은 이름+주소 중복 의심 기록을 **자동으로 검토 대기 목록에만** 분류. 이전 인간 승인·기각 결과 덮어쓰기 없음.
3. 앞선 초기 20건 조사 중 해결되지 않은 11곳의 연구 이슈를 스테이징 품질 대기열에 동일한 `pending`으로 추가.
4. 스테이징 품질 대기열 실제 집계:
   - 좌표 누락: **350**
   - 중복 의심 원본 행: **16**
   - 초기 식당의 영업·지점·메뉴·업종 불일치 조사: **11**
   - 두 주소 모두 누락: **0**
   - 합계 검토 대기 이슈 **377** (식당 고유 건수가 아니라 이슈 행 수임)
   - 검토자 확정 보류: **0건**. **아직 실제 식당을 숨기지 않았음**.
5. 공용 `searchRestaurantCatalog`와 `getRestaurantCatalogDetail` 및 `getGeoCatalog`에서 **확정된 보류 이슈만** Search/식당 상세/지도/nearby 노출 제외하는 동일 정책 구현. **pending은 자동 숨김이 아님**.
6. 검색·지도 검색 결과 주소는 정확한 **도로명 → 지번 주소 순서 fallback**, 검색어 입력으로 지번 주소 직접 검색 가능. 빈 주소를 추측해 생성하지 않음.
7. 검색 결과 '검증된 식당' 오해를 막기 위해 4개 언어 안내 문구를 **공공 인허가 기반 검색 결과이며 현재 영업 상태 미확인**으로 교정.
8. CI 독립 PostgreSQL 합성 fixture에 원장/현재 영업을 가정하지 않는 보류 가상 식당 및 지번 주소만 있는 가상 식당을 생성. 검색/상세/지도·SSR 동시 제외 여부, pending 노출 허용, 지번 주소 탐색, 원본 보존 검증.
9. `scripts/audit_restaurant_quality.mjs`: **읽기 전용 트랜잭션**으로 품질 집계. 실제 Neon production에서 실행하지 못하도록 스테이징 브랜치 확인·명시적 승인 환경변수 요구. 로컬 CI fixture 예외는 별도 `ONLY_LOCAL_EPHEMERAL` 표시 필수.

## 배포 전 경고
- migration 008/009는 **Neon staging `br-autumn-pine-b36z3utm`에만 적용**함.
- 운영 `br-misty-darkness-b3lr98mz`의 식당 10,000건 및 기존 스키마는 수정하지 않음. **신규 API 코드가 quality 테이블에 의존하므로 migration 008을 적용하지 않은 운영 DB와 결합하면 조회 실패(503)가 발생할 수 있음.**
- GitHub main 병합/도메인 배포 전에 **코드·스키마 순서·롤백을 모두 검증한 배포 계획**이 필요하며, 실제 사업자 확인 후의 publish/hide 조치는 별도 검토 단계.
- 8그룹 중복 의심은 `sbiz_source_key`가 서로 다른 독립 인허가 행일 수 있으므로 현재는 그대로 보존·표시. 출처 문서로 동일 사업장임을 확인하기 전 합치지 않음.
- 위경도 누락 350건은 지도에 표시할 수 없지만, 식당명/주소 검색·상세는 유지.
- 전국 서비스 수준 DB는 미완료: 종로/중구에 집중돼 있음.
- 현재 한국어·영어·일본어·중국어 공개 설명/메뉴/사진/독립 점수의 신규 승인 공개는 0건 (스테이징의 28 설명·16 메뉴는 검토 초안 상태).


## 배포 준비 상태 게이트
- `GET /api/ready`는 DB TCP 연결만으로 200을 반환하지 않고 **공개 식당 검색이 의존하는 핵심 schema 004 + 품질 검토 schema 008**이 존재해야 200 응답.
- `WHATEATO_REVIEW_MODERATION_ENABLED=true`일 때는 승인 이력 schema 007도 필요. 없으면 503/migration_required.
- `catalog_quality_schema` 및 `review_moderation_schema` 상태를 no-store JSON으로 보고. 개발자·운영자는 배포 전 순서 004 → 005/006/007 → 008/009를 확인할 것.
- 이 단계는 식당 DB 원본을 자동 삭제/중복 병합하지 않는다. 사용자에게 영업 허가 기록이 실시간 운영 확인을 의미하지 않는다는 검색 화면 문구를 한국어/영어/일본어/중국어 모두에 적용.
- 테스트에서 SQL 삽입 구조 오류와 검색창에 재표시된 검색어를 검색 결과로 오인한 assertion 오류를 발견해 수정. 이후 최종 커밋의 PostgreSQL + 브라우저 QA 통과 여부를 기준으로 품질 게이트 판정.
