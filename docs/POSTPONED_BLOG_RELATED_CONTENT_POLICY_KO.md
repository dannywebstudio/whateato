# WhatEatO — 블로그 후순위 및 노출 정책 (기획 결정, 구현 보류)

2026-10-13 · 사용자 지시: 블로그 기능 개발을 핵심 식당 DB 정리·정제·노출 개발 완료 이후로 연기.

## 콘텐츠 노출 정책 v1 (미구현)
| 위치 | 최대 노출 | 정렬/연결 | 글이 없을 때 |
| --- | ---: | --- | --- |
| Search | 5 | 검색 키워드 연관 게시물, 제목/본문과 식당 ID 직접 연결 우선 | 블로그 영역 숨김, 기존 식당 검색만 표시 |
| Map | 5 | 현재 지도 영역에 표시된 식당 ID와 직접 연결된 글, 중복 제거 | 관련 글 영역 숨김 |
| 식당 상세 하단 | 5 | 해당 식당 UUID에 직접 연결된 공개 글, 품질·신뢰성과 관련성 우선 | 관련 글 영역 숨김 |

- 세 화면 모두 **발행/공개 승인 글만** 노출, 초안·검토·비공개·삭제 글 제외.
- 식당 본문에 삽입된 **검증된 WhatEatO 식당 ID**로 연결; 상호명이 비슷하다는 이유만으로 타 지점 연결 금지.
- 같은 글을 한 섹션 안에 두 번 노출하지 않음. 동점 시 최근 발행일, 게시물 UUID 순 등 안정적 정렬 기준 사용.
- 블로그 URL은 검색어와 매칭되면 식당 결과와 함께 별도 구역으로 출력. 검색에 매칭되는 글이 없으면 레이아웃은 기존 그대로.
- 페이지별 기본 표시 상한 5건. '더보기'는 블로그 기능 개발 시 검토하며, 자동으로 5개 초과 렌더링하지 않음.
- 상업성 글 우대/가짜 별점/검증되지 않은 식당 정보 연결 금지. 이 정책 자체는 코드/운영 스키마를 추가하지 않음.
- 숏폼 영상 업로드 기능도 수익화 이후 재검토, 현재 개발 범위 제외.

## 현재 개발 우선순위
1. 원본 10,000건 데이터 품질·중복 의심·주소·좌표 상태 감사와 비파괴 정리.
2. 공개 API/Search/Map/Detail의 동일한 노출 기준 및 부정확한 '검증된/현재 영업' 오해 방지.
3. 데이터 품질 QA와 실제 PostgreSQL 기반 회귀 테스트.
4. 검증된 식당 데이터 및 관리자 승인 흐름 이후, 이 문서의 블로그 시스템으로 확장.

**현재 블로그 검색/추천/에디터/댓글 DB 및 UI는 구현하지 않음.**
